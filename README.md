# MyLocality – Neighborhood Complaint & Service Request App
Flutter + Firebase Auth + Cloud Firestore · Material 3

## Setup (what YOU need to do)

1. Put this folder anywhere, open a terminal inside it and generate the platform folders:
   ```
   flutter create . --project-name mylocality --platforms=android,ios,web
   ```
   (It will NOT overwrite `lib/` or `pubspec.yaml`.)

2. Create a Firebase project at https://console.firebase.google.com
   - **Authentication → Sign-in method → enable Email/Password**
   - **Firestore Database → Create database** (production mode)
   - **Firestore → Rules** → paste contents of `firestore.rules` → Publish

3. Connect the app to Firebase (this overwrites `lib/firebase_options.dart`):
   ```
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```

4. Android only: in `android/app/build.gradle(.kts)` make sure `minSdk` is at least 23.

5. Run:
   ```
   flutter pub get
   flutter run
   ```
   If versions clash, run `flutter pub upgrade --major-versions`.

## Changing complaint status (Pending → In Progress → Resolved)
Open Firebase Console → Firestore → `complaints` → pick a document →
edit the `status` field to exactly `Pending`, `In Progress` or `Resolved`.
Then pull-to-refresh in the app's My Complaints screen.

## Firestore data model
`complaints/{autoId}`
| field | type |
|---|---|
| userId | string (Firebase uid) |
| userEmail | string |
| category | string |
| description | string |
| status | string (default `Pending`) |
| createdAt | timestamp (server) |

## Justification (for your report)
- **Firebase Auth**: only verified residents can file complaints; every complaint is tied to a uid.
- **Cloud Firestore**: real-time-capable NoSQL cloud DB; status updated by authorities is visible to the resident without app updates.
- **async/await + FutureBuilder**: network calls never block the UI; loading, error and empty states are all handled.
- **Material 3 + colour-coded chips**: status is recognisable at a glance (orange/blue/green plus icon, so not colour-only).
- **Form validation**: prevents empty/low-quality complaints before they reach the cloud.
- **Security rules**: residents can read/create only their own complaints, always as Pending.
- **Responsive**: content is width-constrained so it works on phones, tablets and web.
